## 1. 计划为什么改了：十天 → 六个任务

### 1.1 真实的账

| 项 | 数字 |
| --- | --- |
| 原计划任务数 | 10 个（D1–D10） |
| 实际完成的任务 | **6 个**（D1 地图、D2 异步+大模型、D3 FastAPI、D4 前端集成、D5 工具调用、D6 上线），外带一个半天（D5-E 加时间工具） |
| 被砍掉的任务 | 最小知识库（RAG）、评测集 |
| 日历跨度 | 10/1 → 10/25，**24 天** |
| 真正动手的天数 | 约 **9 天**（10/1、2、3、5、11、15、19、24、25） |
| 至今仍未做的 | **投递**（原计划的最后一天） |

所以准确的说法不是「十天缩成六天」，而是：

> **任务从 10 个变成 6 个，工期从 10 天变成 24 天。**

完成度约 60%，工期用了 240%。中间停顿过几次，最长的一次隔了 5 天没动。

### 1.2 为什么会这样（不是懒，是估算错了）

计划是我按「每天 4–6 小时、连续 10 天」排的。实际情况是：

- 你有课、有导师的事、有生活，**能整块投入的日子不多**
- 有好几天是 0 小时，然后某一天补 5 小时
- 我是按「理想状态」估的工时，没有给「中断」留余量

**教训（写给你，也写给以后排计划的自己）**：给一个每天只能挤出 2–3 小时、还会被课打断的人排计划，**任务数要按 0.6 折算**。10 天的计划，实际能做完 6 天量的事。

### 1.3 为什么砍 RAG 是对的

当时有两个选择：

| 选项 | 好处 | 代价 |
| --- | --- | --- |
| A. 补一个最小知识库（切块 + bigram 检索 + 引用） | 简历多一行「RAG」 | 再花 3–4 小时，而且 **上线继续往后拖** |
| B. 先上线，RAG 以后再说 | 有链接、有演示、有 README | 少一行关键词 |

选 B。理由很硬：

> **没有链接，简历是废的；有链接但少一个 RAG，只是少一行。**

一个人筛简历只花 20 秒。他在这 20 秒里做的是「点不点这个链接」，不是「数你有几个关键词」。

而且 RAG 这个词现在几乎人人会写，写了也未必加分；**一个能点开、能演示、答得出细节的项目，比一个关键词值钱得多。**

## 3. 提问记录

### Q1：为什么在网站提交后，输入网址就能跑代码？以前不是要在这台电脑上开命令行吗？

因为**代码不再跑在你的电脑上**。

以前开命令行，是**你的电脑在扮演服务器**。现在你 `git push` 一下，代码被传到了 GitHub，Vercel 监听到仓库变化，自动拉下来、装依赖、打成函数、挂到一个公网域名后面。

整条链子是这样：

```
你本机改代码 → git push → GitHub → Vercel 监听到变化 → 自动构建 → 域名指向新版本
```

你那台电脑在这条链子里**只负责前两段**。后面全在别人的机房里。

### Q2：现在网站上跑的是我本机的代码，还是网站上的代码？我动本机会出事吗？

**跑的是「你最后一次 push 那一版的快照」。**

所以：

| 你做的事 | 线上会怎样 |
| --- | --- |
| 改本机代码、**不 push** | 线上**毫无变化** |
| 改本机代码、`git push` | 20–30 秒后线上自动更新 |
| 删本机文件夹 | 线上照常运行（它有自己的副本） |
| 把 `.env` 删了 | 线上照常运行（密钥存在 Vercel 的环境变量里，不在仓库里） |

**「出事」的唯一方式**：push 了一版有 bug 的代码。所以正式项目会先开分支、先在预览环境看，确认没问题再合到 `main`。

### Q3：为什么线上不用管跨域，本地要？

**跨域（CORS）只在「页面和接口不同源」时才发生。**

| 场景 | 页面来自 | 接口来自 | 同源？ | 要不要 CORS |
| --- | --- | --- | --- | --- |
| 本地双端口 | `localhost:8000` | `localhost:8001` | ❌ 端口不同 | 要 |
| 线上 | `yanbian-webgis.vercel.app` | `yanbian-webgis.vercel.app/api` | ✅ 同域 | 不要 |

代码里那段判断就是为这件事：

```js
const API_BASE = (location.hostname === 'localhost' || location.hostname === '127.0.0.1')
  ? 'http://localhost:8001'    // 本地：跨端口，写完整地址
  : '';                        // 线上：同源，留空 → 请求 /api/chat
```

**顺带一个白送的好处**：现在 `app.py` 自己会把 `index.html` 交出去，所以本地开 `http://localhost:8001` 就是完整页面，8000 那个终端可以不要了 —— 本地也变成同源了。

### Q4：`.env` 为什么不能跟着一起上传？

因为 `.env` 里是**密钥**，而 GitHub 仓库是**公开**的。上传 = 把你的 API Key 贴到广场上，几分钟内就会有人拿去刷你的额度。

所以：

- `.env` 写进 `.gitignore`（D2 就做过了）
- 线上把密钥放进 **Vercel 的 Environment Variables**
- 代码里统一用 `os.environ.get("DASHSCOPE_API_KEY")` 读 —— 本地从 `.env` 加载，线上从平台注入，**同一行代码两处都能用**

## 4. 核心知识

### 4.1 部署到底改变了什么

一句话：**服务器不再是你家那台电脑。**

| | 本地 | 线上 |
| --- | --- | --- |
| 谁在跑 | 你按了回车才跑 | 有人访问就跑 |
| 关机了怎么办 | 服务就没了 | 不关你的事 |
| 别人能访问吗 | 只有同一局域网 | 全世界 |
| 改代码 | 保存 + 刷新 | `git push` + 等 20 秒 |

### 4.2 Serverless（无服务器）：没有一台「你的」机器

Vercel 不给你一台机器，它给你的是一堆**函数**：`/api/chat` 被访问一次，就启动一个进程、跑完、返回、销毁。

由此带来三个必须知道的后果：

1. **进程里的变量不会留到下次** —— 每次请求可能是全新的进程，别指望用全局变量攒状态
2. **冷启动** —— 一段时间没人访问，下次请求要多花几百毫秒到一两秒
3. **有超时** —— 跑太久会被掐断。所以 `vercel.json` 里写了：

```json
{ "functions": { "api/*.py": { "maxDuration": 60 }, "app.py": { "maxDuration": 60 } } }
```

`maxDuration` = 这个函数最多允许跑多少秒。**不写就用平台默认值，调大模型很容易踩到。**

### 4.3 环境变量：密钥放在仓库外面

```
本地：.env 文件  →  python-dotenv 读进内存  →  os.environ
线上：平台后台填写 →  直接注入进程环境      →  os.environ
                                        ↑
                                  代码只认这一层
```

**代码里永远不要出现明文密钥**，只在 `os.environ` 这一层取值。这样同一份代码，本地和线上都能跑，而仓库里干干净净。

### 4.4 同源 / 跨域，一句话记住

> **同源 = 协议 + 域名 + 端口，三者全一样。**
> 只要有一个不同，浏览器就会先去问一句「后端允许吗」，这就是 CORS 预检。

### 4.5 静态文件在 Vercel 上不一定自动生效

这是今天最反直觉的一条。

一般人的预期：仓库里有 `index.html`，Vercel 就会把它当首页。
实际发生的事：**Vercel 看到根目录有 `app.py`，把它认成「整个项目的入口」，于是所有请求都交给了这个 Python 应用** —— 包括 `/` 和 `/app.js`。

证据是那个 404 的**长相**：

```
{"detail":"Not Found"}
```

这是 FastAPI 的 404 格式。如果是 Vercel 自己的静态 404，会返回一个 HTML 页面。**看到一个 JSON 的 404，就知道这个请求根本没到静态文件那一层，是被 Python 接住了。**

修法（`app.py` 里用白名单，不整目录挂载）：

```python
@app.get("/", include_in_schema=False)
def page_index():
    return FileResponse(os.path.join(BASE_DIR, "index.html"),
                        media_type="text/html; charset=utf-8")
```

**为什么不整目录挂载**：那会把 `app.py`、`notes/`、`requirements.txt` 全变成可下载的网页。用白名单只放行 4 个文件（`index.html` / `app.js` / `style.css` / `yanbian.geojson`），干净。

## 5. 错误记录（今天 5 个坑）

### 错误 1：Hugging Face 的 Docker 空间要付费

HF 的 Space 有三种 SDK：Static（免费）、Gradio（**Paid**）、Docker（**Paid**）。
我们要跑 FastAPI，只能用 Docker —— 而它已经变成付费的了。

**教训**：选部署平台时，**先看免费额度覆盖不覆盖你的技术栈**，别先写代码。

### 错误 2：Render 要求验证信用卡

表单弹出来就要填卡号（`temporary authorization for $1 USD`）。
「免费额度」不等于「免费注册」—— 很多平台要靠一张卡来防滥用。

**教训**：一个平台能不能用，取决于 **支付方式**，不只是免费计划。学生没有双币卡的话，优先选 GitHub 账号直登的平台。

### 错误 3：`Internal Server Error`（500）—— 浏览器一个字都不肯多说

浏览器上只有一行 `Internal Server Error`。**这不是报错，这是「出事了」的通知。**

真正的问题是密钥：`.env` 里的密钥和线上填的不一致 / 多了空格换行，导致调用大模型时返回 `401`。

**怎么定位的**：加一个「体检接口」，一次性回答所有可能的问题：

```
/api/diag  →  {"python 版本":"3.12.14","密钥已注入":true,"密钥前 6 位":"sk-ws-…",
               "密钥长度":116,"密钥后 4 位":"XUis","末尾是否有换行或空格":false,
               "模型地址":"https://dashscope.aliyuncs.com/compatible-mode/v1/",
               "模型调用":"成功","耗时秒":1.92,"模型回复":"好"}
```

**这个设计值得记住**：与其在聊天里问「你密钥贴对了吗」，不如让程序自己回答。

另外那个 `chat` 接口外面包了 `try/except`，把异常原样返回：

```python
except Exception as e:
    return {"回答": f"（后端错误）{type(e).__name__}: {str(e)[:300]}"}
```

这样才能在浏览器里直接看到 `AuthenticationError` / `401`，而不是一个光秃秃的 500。

### 错误 4：线上首页 `{"detail":"Not Found"}`

见 4.5。**关键判断：404 的「长相」告诉你是谁在拒绝你。**

| 404 长什么样 | 谁在说 |
| --- | --- |
| `{"detail":"Not Found"}` | FastAPI（请求到了 Python） |
| 一整页 HTML（404 Not Found / 灰色） | Vercel 的静态服务（文件真不存在） |

### 错误 5：我一开始也选错了平台（HF → Render → Vercel，换了两轮）

三次尝试，两次失败。**这不是浪费时间，这就是排查的正常成本** —— 只是下次可以先花 5 分钟把「免费 + 不要卡 + 支持 Python」三个条件查清，再动手。

## 6. 调试工具箱（部署日新增）

### 一条命令判断「是文件没到，还是内容不对」

```powershell
curl.exe -s -o NUL -w "%{http_code}|%{content_type}|%{size_download}" https://你的域名/
```

三个字段各有含义：

| 字段 | 看什么 |
| --- | --- |
| `%{http_code}` | 200 = 到了；404 = 没这个文件；500 = 后端崩了 |
| `%{content_type}` | **最有用的一个**：看到 `application/json` 就说明是 Python 返回的，不是静态文件 |
| `%{size_download}` | 字节数对不对。首页 2 KB 左右正常，4 字节说明只返回了一个空壳 |

### 抓一段真实内容（而不是只看状态码）

```powershell
curl.exe -s "https://你的域名/api/chat?q=延吉到珲春多远"
```

**状态码 200 不代表内容对。** 要真的把返回看清楚。

### 等部署，别靠猜

```powershell
for ($i=1; $i -le 24; $i++) {
  Start-Sleep -Seconds 10
  $body = & curl.exe -s "https://你的域名/style.css"
  if ($body -match "--accent") { "新版本已上线"; break }
}
```

找一个**只有新版本才有的特征**（比如新加的 CSS 变量名），轮询它。比反复刷新页面靠谱。

### 接口文档也是排查工具

`/docs` 和 `/openapi.json` 能告诉你「后端到底注册了哪些路由」。
如果某个接口在 `openapi.json` 里根本不出现，那不是前端请求错了，是**后端压根没这个路由**。

## 7. 高频易错 8 条

1. `.env` 千万别提交。上传前跑一次 `git status`，看一眼待提交列表
2. 线上 500 时，**先看后端自己的日志/诊断接口**，别盯着浏览器
3. **`200` 不代表成功**，要看返回内容
4. 404 的**格式**决定是谁拒的（JSON = Python，HTML = 静态服务）
5. 免费额度 ≠ 免费注册，先确认支付方式
6. 部署后前端要改 `API_BASE`，否则线上还在请求 `localhost:8001`
7. `maxDuration` 一定要配，大模型调用的耗时不可控
8. `git push` 之后要**等**，20–30 秒才会生效；急着刷新只会以为失败了
