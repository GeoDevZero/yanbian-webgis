# FastAPI & 跨域 & fetch res.text() / res.json() 笔记（可直接放进md）
## 一、FastAPI 最小结构
`@app.get("/api/xxx")` 装饰器 + 函数 + return 字典
- `@app.get("/api/xxx")`：注册GET接口，浏览器访问该路径，就执行下方函数
- 函数：写业务逻辑（读文件、计算、查询）
- return 字典：FastAPI自动把python字典转为JSON返回前端

### `app:app` 含义（文件名:变量名）
格式：`模块名:app实例`
> 比如文件名叫 `main.py`，里面写了 `app = FastAPI()`
> 启动命令 `uvicorn main:app`
1. **main**：`main.py`，文件名（去掉`.py`后缀），也就是python模块名
2. **app**：在main.py代码里定义的变量 `app = FastAPI()`，这个变量是服务实例
> 理解：去main这个文件里，找到名叫app的对象，作为web服务启动
> 类比：`gis:app` 就是 gis.py 里面 `app=FastAPI()`

## 二、CORS 为什么是后端的责任
> 核心：**跨源限制是浏览器的安全策略**，端口不同、域名不同、协议不同都算跨源。
> 同源 = 域名 + 端口 + http/https 三者全部一致；只要一项不一样，就是跨源。

1. 流程：前端JS(fetch)发起跨域请求 → 浏览器先发**预检OPTIONS请求**给后端
2. 浏览器不会直接拦死请求；**浏览器会看后端返回的响应头 `Access-Control-Allow-Origin`**
   - 后端没配置CORS：响应头不存在 → 浏览器拿到响应后，直接拦截JS读取结果，前端报CORS错误
   - 后端配置CORS中间件，返回允许跨域的头部 → 浏览器放行，前端JS可以拿到数据

✅ 为什么是后端责任：
浏览器只是执行安全校验；**是否允许前端页面跨域访问接口，决定权在后端服务器**。后端添加响应头，告诉浏览器：这个来源的前端，是被我信任的，允许读取返回数据。
> 端口不同 = 跨源。例如前端Leaflet页面`http://127.0.0.1:5500`，FastAPI接口`http://127.0.0.1:8000`，端口不一致 → 跨源。
> 解决：后端FastAPI引入`CORSMiddleware`配置。

```python
# FastAPI CORS最简示例
from fastapi.middleware.cors import CORSMiddleware
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"], # *代表允许所有来源，开发用；生产不要*
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

## 三、`res.json()` 与 `res.text()` 对比（fetch实验）
> `res.json()` ≈ `JSON.parse(await res.text())`

### 1. 两个方法的本质
- `await res.text()`：**拿到原始字符串**（纯文本，就是服务器返回的JSON文本，类型是string）
- `await res.json()`：读取响应文本，**自动执行JSON.parse，直接得到JS对象**

### 2. 对比实验代码（可以直接在浏览器控制台运行）
```js
// fetch你的FastAPI接口
const res = await fetch("http://127.0.0.1:8000/api/stats");

// 方式A：text + 手动parse
const txt = await res.text();
console.log("txt类型:", typeof txt); // string
const objA = JSON.parse(txt);
console.log("objA", objA, typeof objA); // object

// ⚠️注意：res是一次性流！上面await res.text()读完流，下面res.json()会报错
// 想要同时测试，需要克隆response
const res2 = await fetch("http://127.0.0.1:8000/api/stats");
const objB = await res2.json();
console.log("objB", objB, typeof objB); // object
```

### 3. 关键区别&易错点
1. Response是**一次性可读流**：一旦`await res.text()`读完，这个res里面的数据就空了，**不能再调用res.json()**，会报错。想多次读取，要用`res.clone()`
2. `res.json()`会自动校验文本是否合法JSON。如果后端返回普通文字（不是JSON），`res.json()`直接抛出异常；`res.text()`不会报错，原样拿到字符串。
3. 简单总结：
    - 后端返回JSON → 直接用 `await res.json()`，省事，直接得到JS对象
    - 后端返回普通文本/html → 用 `await res.text()`

### 一句话记忆
`res.text()`：拿**字符串**；`res.json()` = 拿字符串 + 自动JSON.parse，得到**JS对象**。

## 极简背诵版
1. `uvicorn 文件名:app`：文件名（模块）:文件内FastAPI实例变量
2. CORS：浏览器同源策略，端口不同即跨源；后端加响应头告诉浏览器放行，所以是后端责任。
3. fetch：`res.text()`获取原始字符串；`res.json()`等价`JSON.parse(await res.text())`，直接得到对象；response流只能读一次。
