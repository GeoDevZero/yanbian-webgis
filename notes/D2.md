## 三、JSON 相关

### JSON.stringify()
- 本义：`string` 字符串，`ify` 使…变成
- 作用：**JS 对象 → JSON 字符串**
```js
const obj = {a:1}
JSON.stringify(obj) // '{"a":1}'
```

### JSON.parse()
- 本义：`parse` 解析
- 作用：**JSON 字符串 → JS 对象**
```js
JSON.parse('{"a":1}').a // 1
```
> ⚠️易错：JSON 字符串**只能用双引号**，单引号会直接报错
> 错误：`JSON.parse("{'a':1}")`

> 💡 **为什么要来回转换**：HTTP 传输的只能是**文本**，不能直接传对象。发出前 `stringify`，收到后 `parse`。
> 回头看：`res.json()` 干的就是 `JSON.parse`。

### pop / pop-up
1. `pop`：在 geojson 属性里一般是 `pop = population` 人口数值，例 `pop:50` 代表人口50
2. `popup`：弹窗，leaflet 绑定弹窗方法 `bindPopup()`

> ⚠️ **这两个词很容易混**，一个在 `properties` 里（数据），一个是地图交互方法（UI）。分开记。

## 四、Promise 异步

### resolve
- 本义：解决
- Promise 内部函数：`resolve(数据)`，把 Promise 置为成功状态，向外传出数据，交给 `.then()` 接收
- 配对：`reject(错误信息)`，标记失败，交给 `.catch()`

### .then()
```js
const p = new Promise(resolve=>{
  setTimeout(()=>resolve('3 秒到了'),3000)
})
p.then(v=>console.log('4 '+v))
```
- `p`：Promise 盒子对象（任务容器）
- `v`：自定义参数，接住 `resolve()` 抛出来的数据，名字可以改成 `data / msg`，不要和外部变量重名
- `.then()` 只是注册回调，不会立刻执行；**等 resolve 触发才运行**

> ✅ **精确化（重要）**：`.then()` 的回调**永远不会"同步立刻"执行**——它总是被排进**微任务队列**，等当前这段同步代码全部跑完后才执行。
> 所以有两种"快慢"：
> - Promise 还是 **pending** → 等 resolve 后，再排队执行
> - Promise 已经 **fulfilled** → 当前同步代码一跑完，**马上**执行（不用再等定时器）
>
> **这条正好解释了第九章"错误 1"里那个现象。**

**Promise 的三种状态（不可逆）**：

| 状态 | 本义 | Console 里显示 |
|---|---|---|
| pending | 悬而未决 | `Promise {<pending>}` |
| fulfilled | 已履行 | `Promise {<fulfilled>: 值}` |
| rejected | 已被拒绝 | `Promise {<rejected>: 错误}` |

> ⚠️ **状态不可逆**：一旦 fulfilled 就永远是 fulfilled。所以之后任何时候 `.then()`，回调都会被"排队后立刻执行"。
> 同一个 Promise 可以 `.then()` 很多次，全都拿到同一个结果。

### 异步执行顺序示例
```js
console.log('1 开始');
const p = new Promise(resolve => setTimeout(() => resolve('3 秒到了'), 3000));
console.log('2 我不管它，先往下走');
p.then(v => console.log('4 ' + v));
console.log('3 我也先走');
```
输出顺序
```
1 开始
2 我不管它，先往下走
3 我也先走
//等待3秒
4 3 秒到了
```
> 核心：**同步代码全部优先跑完，再处理异步回调**，定时器不会阻塞主线程。

> ⚠️ **实验条件**：这段必须**一次性执行**（整段粘贴）。一行一行手敲会破坏时序——见第九章"错误 1"。

## 五、async / await

> Promise 语法糖，让异步代码写起来像同步

1. 语法强制：`await` **只能写在带 async 标记的函数内部**
2. `await promise对象`：暂停**当前 async 函数内部**代码，等待 Promise 成功 resolve，拿到返回结果赋值给变量；**不会阻塞函数外面代码**
3. 失败捕获：搭配 `try-catch` 处理 `reject` 报错

```js
async function run(){
  try{
    const res = await p
    console.log(res)
  }catch(err){
    console.log("出错",err)
  }
}
run()
```

> ✅ **精确化（很重要）**：说"顶层直接写 await 会报错"**只在普通 `<script>` 标签里成立**。
> 在下面两种场合，顶层 await 是**合法**的：
> - ✅ **浏览器 Console**（所以你可以直接敲 `await fetch('./yanbian.geojson')` 回车看结果，很好用）
> - ✅ **ES 模块**（`<script type="module">`）
> - ❌ 普通 `<script>`（我们 `index.html` 现在这种）→ 必须包在 `async function` 里
>
> **为什么会有这个差别**：模块和 Console 有"顶层等待"的机制，普通脚本没有。

### 异步 —— 我自己的定义（已修正）

我原来的说法（80% 对）：
> 异步就是先不执行这行代码，先把下面的代码跑完，等后面满足了异步的条件后再执行异步代码

✅ 对的部分：**"先不执行、先往下跑"** —— 这就是异步的本质。
⚠️ 要精确的部分："满足了异步的条件"太模糊。

**修正后的标准说法**：
> **异步**：遇到"**要等外面的事**"（网络、定时器、读文件）时**不干等**，先往下执行；
> 等那件事**有结果了**，再回过头执行"结果回来后该做的事"（`then` / `await` 后面的代码）。

**关键词**：**"等外面的事"** + **"有结果了"**。面试说到这两个点就到位了。

#### 搭配 fetch（GIS 高频）
```js
// .then写法
fetch("data.json")
.then(resp=>resp.json())
.then(data=>console.log(data))

// async await写法
async function load(){
  const resp = await fetch("data.json")
  const data = await resp.json()
  console.log(data)
}
load()
```

## 六、Leaflet 地图 API

### map.fitBounds(layer.getBounds())

1. `layer.getBounds()`
获取图层地理边界，返回 `LatLngBounds` 对象，存储西南、东北角经纬度；支持 marker、面、featureGroup、GeoJSON 图层。

2. `map.fitBounds(bounds)`
地图自动平移+缩放，完整显示地理范围，自带留白边距。

```js
//基础写法
const layer = L.geoJSON(geojsonData).addTo(map);
map.fitBounds(layer.getBounds());

//带配置
map.fitBounds(layer.getBounds(), {
  padding: [20,20], //四周留白
  maxZoom:12 //限制最大缩放等级
})
```

> ⚠️坑点
> 1. 图层为空时 `getBounds()` 可能**返回 undefined，也可能返回一个无效的 bounds**，需要先判断有效性
```js
const bounds = layer.getBounds();
if (bounds && bounds.isValid()) {      // ← 加 bounds && 更稳：先排除 undefined，再判断有效性
  map.fitBounds(bounds)
}
```
> 2. 不要和 `map.setView` 同时写，后面执行的会覆盖地图视图
> 3. 异步加载 GeoJSON，**等图层创建完毕再调用 fitBounds**
>    （这就是 D2 学 `await` 的直接用途：`const data = await res.json();` 之后才建图层）

### onEachFeature

`L.geoJSON` 的专属配置项，遍历每一个 geojson 要素，要素生成图层时执行回调。

```js
onEachFeature: (f, lyr) => lyr.bindPopup(f.properties.name || '未命名')
```
- `f`：feature，原始 geojson 单个要素；`f.properties` 读取属性字段
- `lyr`：layer，leaflet 生成的地图图层
- `lyr.bindPopup()`：给要素绑定点击弹窗，不会自动弹出，点击才显示
- `A || B` 逻辑或：A 不为空/undefined 使用 A，否则使用 B 默认值

完整示例
```js
L.geoJSON(geojsonData,{
  onEachFeature:(f,lyr)=>{
    lyr.bindPopup(`名称：${f.properties.name || '未命名'}`)
  }
}).addTo(map)
```

> 💡 顺带记住：上面用到了 **模板字符串**（反引号 + `${}`），它和你 D1 笔记里 JS 学的 `15-模板字符串.html` 是同一个东西。

## 七、Git 密钥安全 .env / .gitignore

1. `.env`：环境变量文件，存放 API-KEY、密钥、密码等敏感信息，密钥不要直接写业务代码。
```env
DASHSCOPE_API_KEY=你的百炼key
```

2. `.gitignore`：告诉 git 哪些文件**不要追踪，不要 push 上传 github**
```gitignore
.env
__pycache__/
*.pyc
```

> 铁律：密钥放进 `.env`；`.env` 写进 `.gitignore`
> - 写进 gitignore 之后，`git add` / `git push` 会跳过 .env，密钥不会上传公开仓库，避免被盗刷扣费。

> ⚠️ 坑：如果已经 `git add` 提交过 `.env`，之后再写 gitignore 是**无效的**，需要额外命令移除仓库内记录。
> **补救命令**（D2 补充）：
> ```bash
> git rm --cached .env          # 从"被追踪"变成"不追踪"，但本地文件保留
> git commit -m "移除误提交的密钥"
> ```
> **注意**：这样只是不再跟踪，**历史提交里仍然有密钥**。如果已经 push 过，**正确做法是去平台把密钥作废重新生成**，而不是只删文件。

> 📌 **实际案例（本次真实发生）**：项目文件夹里出现过从百炼控制台下载的 `默认业务空间-apiKey-7550774.csv`（明文密钥），已**永久删除**并加入 `.gitignore`（`*apiKey*.csv`）。
> **教训**：密钥只放 `.env`；下载的密钥文件用完就删。

## 八、`then` → `async/await` 机械配方（背下来）

### 口诀
> ### `then` 变 `await`，回调参数变等号左边。

### 对照表

| 旧写法 | 新写法 |
|---|---|
| `fetch(url).then(res => ...)` | `const res = await fetch(url);` ← 回调参数直接变成等号左边 |
| `.then(data => ...)` | `const data = await 上一步那个 Promise;` |
| `.catch(err => ...)` | 把上面全部包进 `try { }`，写成 `catch (err) { ... }` |
| （最外层） | 套一层 `async function 名字() { ... }`，**末尾别忘了 `名字();`** |

### 两条补充规则
1. **特殊规则**：如果 then 的回调体本身是"另一个 Promise"（如 `res.json()`）→ **再 await 一次**
   `const data = await res.json();`
2. **补充规则**：如果 then 的回调**有返回值**，且后面还有 then → 用 `const 下一个参数 = 那个返回值` **接住它**

### 4 步操作法
1. **最外面套壳**：`async function loadMap() { ... }`，末尾加 `loadMap();`
2. **每个 then**：删掉 `.then(`、`=>`、`)`，改成 `const 参数 = await 前面的东西;`，把原来的内容**搬到下一行**
3. **最后的 catch**：整块包进 `try { }`，写成 `catch (err) { 原内容 }`
4. **保存 → 刷新 → 看控制台**

### 完整实例（项目里真正用的那一段）

```js
// 旧写法
fetch('./yanbian.geojson')
  .then(res => res.json())
  .then(data => {
    const layer = L.geoJSON(data, {
      style: { color: '#c00', weight: 1.5, fillColor: '#f66', fillOpacity: 0.2 },
      onEachFeature: (f, lyr) => lyr.bindPopup(f.properties.name || '未命名')
    }).addTo(map);
    map.fitBounds(layer.getBounds());
  })
  .catch(err => console.error(err));
```

```js
// 新写法
async function loadMap() {
  try {
    console.log('开始读取 GeoJSON...');
    const res  = await fetch('./yanbian.geojson');
    const data = await res.json();
    console.log('读到了 ' + data.features.length + ' 个要素');

    const layer = L.geoJSON(data, {
      style: { color: '#c00', weight: 1.5, fillColor: '#f66', fillOpacity: 0.2 },
      onEachFeature: (f, lyr) => lyr.bindPopup(f.properties.name || '未命名')
    }).addTo(map);

    map.fitBounds(layer.getBounds());
  } catch (err) {
    document.body.innerHTML =
      '<pre style="color:red;padding:20px">读取 GeoJSON 失败：' + err + '</pre>';
  }
}
loadMap();
```

### 错误 1：手敲实验，把实验条件破坏了 ⭐有意思

**我看到的输出顺序**：
```
1 开始
2. 我不管她，我先走
4 3秒到了        ← 立刻出现，不是 3 秒后！
3. 我也先走
```

**原因**：我**一行一行敲**，每行之间隔了好几秒。等敲到 `p.then(...)` 时，3 秒定时器**早就到点了**，Promise 已经完成 → `.then` 的回调被排队后立刻执行。

**证据（截图里就有）**：
```
Promise {<fulfilled>: undefined}
          ^^^^^^^^^^ 已履行 = 已经完成
```
如果没到点，这里会显示 `<pending>`。

**收获（比原实验还多）**：
1. JS 是"一次执行到底"的，5 行代码几毫秒就跑完，中间不会停
2. `setTimeout` 不是"暂停"，是"**登记一个稍后执行的任务**"，然后立刻返回
3. `.then()` 的回调要不要等，**取决于 Promise 现在什么状态**（对应第四章"精确化"那条）

**正确做法**：把多行**一次性粘贴**执行（Console 会被拦 → 先输入 `allow pasting` 解锁），或用单行版一次回车。

### 错误 2（核心误解）：以为每个 `.then` 都要"重新发起一次"那个 Promise ⭐⭐⭐

**我提交的答案：**

练习 2 ❌
```js
async function f1(){
  const name = await Promise.resolve('延边州');
  name + ' 有 8 个县市';                            // ❌ 算出来了，但没接住 → 结果丢了
  const text = await Promise.resolve('延边州');      // ❌ 又跑了一趟仓库，而且完全没用上 name
}
f1();
```

练习 3 ❌
```js
async function f1() {
  const res  = await fetch('./yanbian.geojson');    // ✅ 对
  const data = await res.json();                    // ✅ 对
  const data = await fetch('./yanbian.geojson');    // ❌ 多余的一行（还会因重复声明直接报错）
  console.log('要素数：' + data.features.length);
}
f1();
```

**错误特征**：`Promise.resolve('延边州')` 写了两遍，`fetch(...)` 也写了两遍。

**根因**：
> ❌ 我以为：每个 `.then` 都要重新发起一次那个 Promise
> ✅ 真相：**一个 Promise 只发起一次。链条上的每一步，只是"接住上一步的产物继续加工"。**

**流水线比喻**：
```
fetch(...)        ← 去仓库取原料（只取一次！）
   ↓ 产出：Response
第一个 .then      ← 第一道工序
   ↓ 产出：数据
第二个 .then      ← 第二道工序，加工【第一道工序的产出】，不是再跑一趟仓库
```
**为什么第二个 `.then(t => ...)` 里的 `t` 就是上一步的结果？** 因为 `then` 的参数，定义上就是"上一步给我的东西"。

**练习 2 正确写法 ✅**
```js
async function f2() {
  const name = await Promise.resolve('延边州');   // 第一道工序
  const text = name + ' 有 8 个县市';             // 第二道工序：加工 name
  console.log(text);
}
f2();
```

**练习 3 正确写法 ✅**（就是删掉多余那行）
```js
async function f3() {
  const res  = await fetch('./yanbian.geojson');
  const data = await res.json();
  console.log('要素数：' + data.features.length);
}
f3();
```

### 错误 3：算出来的值"没接住"

```js
name + ' 有 8 个县市';    // ❌ 算完就扔了，没赋给任何变量
```
**正确**：`const text = name + ' 有 8 个县市';`

**JS 事实**：`await` 一个**普通值**（不是 Promise）也合法，会直接返回它本身。所以写 `const text = await (name + ' 有 8 个县市');` 也能跑——**但多余，不是异步的东西不需要 await**。

## 十一、高频易错考点 + 速记口诀

### 易错考点

1. **一个 Promise 只发起一次**，后面的 `.then` 是**加工上一步的产物**，不是重新请求 ⭐⭐⭐
2. then 回调**有返回值**时，要 `const 下一个参数 = ...` **接住它**，否则结果丢失
3. `.then()` 回调**永不"同步立刻"执行**，它排进微任务队列；Promise 已完成则在当前同步代码跑完后立刻执行
4. `await` 只能写在 `async` 函数里（普通 `<script>` 中）；`async` 函数一定返回 Promise
5. `await` 只暂停**当前函数**，不暂停整个程序
6. `await` 一个普通值也合法，但没必要
7. **调试异步代码必须"一次性执行"**，一行一行手敲会破坏时序
8. Promise 状态**不可逆**：`{<pending>}` / `{<fulfilled>: 值}` / `{<rejected>: 错误}`
9. 浏览器 Console 拦粘贴 → 先输入 `allow pasting`
10. **前端代码必须跑在服务器上**，不能双击 html（同源策略，见 `D1.md`）
11. `bounds && bounds.isValid()` 才算完整的空图层防御
12. **已经提交过的 `.env`，光加 `.gitignore` 无效**，密钥要作废重发

### 速记口诀

1. **JSON**：`stringify` 对象转字符串；`parse` 字符串转对象，**JSON 只能双引号**
2. **Promise**：`resolve` 传出成功数据，`then` 接收；`reject` 抛出错误，`catch` 接收
3. **async await**：`await` 只允许在 `async` 函数里面，只暂停本函数内部
4. **Leaflet**：`getBounds` 拿边界，`fitBounds` 适配视图；`onEachFeature` 遍历每个要素绑定弹窗
5. **密钥安全**：密钥放 `.env`，`.env` 加入 `.gitignore`，绝不 push 密钥上 GitHub
6. **（新增）Promise 流水线**：原料只投一次，后面每一步只加工上一步的产出
