## 2. 提问记录（六问六答）

### Q1：`tool_calls` 是模型真的调用了函数吗？

**不是。** 模型从头到尾没调用过任何函数，它连函数存在都不知道。

它做的事只有一件：**逐 token 预测下一个词**。当它预测到该「调工具」时，输出的是这样一段结构化文本：

```json
{
  "content": null,
  "finish_reason": "tool_calls",
  "tool_calls": [{
    "id": "call_abc123",
    "type": "function",
    "function": {
      "name": "calc_distance",
      "arguments": "{\"from_name\": \"延吉市\", \"to_name\": \"珲春市\"}"
    }
  }]
}
```

**真正执行函数的是你的代码**：

```python
for tc in msg.tool_calls:                    # ← 你写的
    args = json.loads(tc.function.arguments) # ← 你写的
    result = TOOL_IMPL[tc.function.name](**args)  # ← 你写的，这一行才真的算了
```

三者的分工：

| 角色 | 干了什么 |
|---|---|
| 你的代码 | 组装 messages + TOOLS，POST 出去；之后执行函数、回填结果、再 POST |
| API 服务端 | 把 TOOLS 按模板塞进提示词；把模型输出用**约束解码**钉成合法 JSON |
| 模型 | 续写 token。**没有状态、没有记忆、不知道工具执行了没有** |

### Q2：为什么不写 `if` 它就知道该调哪个工具？

因为**它不是规则映射，是概率映射**。

| | `if` 判断 | 模型判断 |
|---|---|---|
| 输入 | 一个布尔值 | 整段对话的**语义向量** |
| 依据 | 你枚举的条件 | 训练出来的权重 |
| 输出 | 确定 | 一个概率分布，采样得到 |
| 没见过的情况 | 走 else，或崩 | 靠语义近似推断 |

它不是「天生会」，是**两个阶段造出来的**：

**① 训练期（SFT / 指令微调）**
厂商用海量样本喂它，每条样本长这样：

```
输入：一段对话 + 一份工具清单
输出：要么正常回答，要么一段 tool_call
```

**关键：样本里既有「该调」的正例，也有「不该调」的负例。**
所以它学到的是**判断**，不是「看到工具就无条件调用」。

**② 推理期（模板 + 约束解码）**
- 你的 `TOOLS` 清单被序列化成特定格式，拼进提示词
- 模型输出被 grammar / 约束解码限制成「合法的 tool_call JSON」

你写一行 `client.chat.completions.create(...)`，里面装的就是这两层。**看不到，但都在。**

### Q3：`description` 为什么能影响它的判断？

因为 **`description` 被拼进了提示词，成了模型能看见的上下文**。

模型做的是**语义匹配**，不是字符串匹配。所以：

| `description` 写成 | 问「延吉到珲春开车要多久」时 |
|---|---|
| 「计算两个城市之间的直线距离」 | 调了（但语义相邻 ≠ 等价）|
| 「查询明天的天气预报」 | 不调（改了描述，行为立刻变）|

**这就是 Part A 里 A3 那个实验的意义：一句话改写，行为就变了。**

写 `description` 的三条规矩：

1. **写「做什么」，更要写「不做什么」** —— 边界比功能重要
2. **写单位、取值范围、格式** —— 否则它填 `"100km"` 而不是 `100`
3. **写什么时候该用、什么时候别用** —— 这是最容易漏的一条

### Q4：为什么「描述了边界」它还在编？

真实翻车记录（同一天，同一个问题）：

| 次数 | 它给出的 |
|---|---|
| 第 1 次 | 直线 69.4 公里，「实际驾车通常需 **1.5 至 2 小时**」 |
| 第 2 次 | 直线 69.4 公里，「实际驾车距离通常更长（约 **75–85 公里**），约需 **1 到 1.5 小时**」 |

两次数字都不一样，而且都跟真实情况（约 103 公里、1.5 小时）有偏差。

**原因：`Tool` 的 description 只约束「调不调、怎么填参数」，管不住「拿到结果之后怎么说话」。**

所以我加了两层保险：

**第一层：代码兜底（不靠模型自觉）**

```python
# 只要调过距离工具，就强制带上这句 —— 由 Python 拼，不是模型写
if any(a.get("类型") == "line" for a in map_actions):
    回答 += "\n\n（以上为球面直线距离，不含道路与路况信息；驾车距离与时间请以导航为准。）"
```

**第二层：把估算交给代码算，不让模型估**

新增 `estimate_drive_time(distance_km, avg_speed_kmh)` 工具：
`69.4 ÷ 60 = 1.157 小时 = 1 小时 9 分`。**这个数字是 Python 算的，不是它编的。**

> **这一课比工具调用本身更重要：**
> 凡是能被代码算准的，就别让模型「说」。
> 模型的自由度，要压缩到只剩下「判断意图」这一件事。

### Q6：同一个坑，我怎么犯了两次？

前端加 `applyMapActions` 之后，**没有做故障隔离**。

第一次我说了，我没改 → 结果绘图一抛错（`actionLayer.getBounds is not a function`），`catch` 把**整个回答**覆盖成错误信息。模型明明答对了，用户一个字都看不到。

```js
// ❌ 错：绘图和取数据共用一个 try
try {
  const data = await r.json();
  显示回答(data.回答);
  applyMapActions(data.地图动作);   // 这里一抛错，上面的回答全没了
} catch (e) {
  显示("出错了：" + e.message);
}

// ✅ 对：绘图单独包一层，各自失败
try {
  const data = await r.json();
  显示回答(data.回答);
  try {
    applyMapActions(data.地图动作);
  } catch (e) {
    console.error("绘图失败（不影响回答）:", e);
  }
} catch (e) {
  显示("出错了：" + e.message);
}
```

**这个模式叫「故障隔离」**：两块功能不该共用同一个错误出口。地图挂了，用户至少还能看到答案。

**为什么我会犯两次？** 因为我是「按提示逐条改」，改完就往下走，没有回头逐条划掉清单。

> **教训：改完要逐条对照清单划掉，不能靠记忆「我记得改了」。**

## 3. 核心知识

### 3.1 Agent 循环的五个要素

```python
for _ in range(5):                                    # ① 必须设次数上限
    msg = client.chat.completions.create(
        messages=messages, tools=TOOLS, ...           # ② 每次都要带 tools
    ).choices[0].message

    messages.append(msg)                              # ③ 把它的「点单」原样记进历史

    if not msg.tool_calls:                            # ④ 不调了 = 说完了，退出
        return ...

    for tc in msg.tool_calls:
        args = json.loads(tc.function.arguments)
        result = TOOL_IMPL[tc.function.name](**args)
        messages.append({
            "role": "tool",
            "tool_call_id": tc.id,                     # ⑤ 身份证，必须对上
            "content": json.dumps(result, ensure_ascii=False),
        })
```

五条铁律：

1. **循环必须有上限**（`range(5)`）—— 不然模型可能无限调下去，烧钱
2. **每一轮都要带 `tools`** —— 忘了带，它就不会调了
3. **模型的消息要原样 append** —— 包括 `tool_calls`，否则历史不完整
4. **`tool_call_id` 必须等于 `tc.id`** —— 一次调多个工具时，靠它配对
5. **`content` 必须是字符串** —— `json.dumps(...)`，不能直接塞 dict

### 3.2 工具三件套

| 名字 | 给谁看 | 作用 |
|---|---|---|
| `TOOLS` | **模型看** | 告诉它「有哪些工具、干什么、参数怎么填」 |
| `TOOL_IMPL` | 你的代码用 | 名字 → 真正的 Python 函数，调度表 |
| `SYSTEM_PROMPT` | **模型看** | 行为纪律（「必须调工具，不许自己估」） |

**`TOOLS` 是接口契约，`TOOL_IMPL` 是实现。两者靠 `name` 对上。**

### 3.3 经纬度顺序：三个地方不一样

| 场景 | 顺序 | 例子 |
|---|---|---|
| GeoJSON 规范 | `[经度, 纬度]` | `[129.5, 42.9]` |
| 你的 `make_buffer` 返回 | `[经度, 纬度]`（跟随 GeoJSON） | |
| **Leaflet** | **`[纬度, 经度]`** | `L.circle([42.9, 129.5])` |

**搞反的症状：地图跳到南美洲，或者 fitBounds 后一片空白/一片海洋。**

因为纬度范围是 ±90、经度是 ±180。`[129.5, 42.9]` 当纬度用 → 129.5 > 90 → Leaflet 直接失效。

### 3.4 `L.layerGroup` vs `L.featureGroup`

```
L.LayerGroup      ← 只是收纳盒：addLayer / clearLayers / eachLayer
      ↑
L.FeatureGroup    ← 继承收纳盒，再额外获得 4 样：
                    getBounds() / setStyle() / bringToFront() / bringToBack()
```

| | 能不能算整体范围 |
|---|---|
| `L.layerGroup()` | ❌ **没有 `getBounds`** |
| `L.featureGroup()` | ✅ 有 |

`layerGroup.getBounds()` 直接报 `TypeError: actionLayer.getBounds is not a function`。

**为什么 featureGroup 能给？** 因为它订阅了每个子图层的 add/remove 事件，知道里面有什么，才能算出包围盒。layerGroup 只管「装」，不关心「装了什么」。

**自检命令：**

```js
typeof L.LayerGroup.prototype.getBounds     // "undefined"
typeof L.FeatureGroup.prototype.getBounds   // "function"
```

### 3.5 城市「中心点」有三个来源，差别 20–50 公里

这是今天最意外的一课。同一个「延吉市中心」，GeoJSON 里有三种算法能得出：

| 来源 | 含义 | 偏差 |
|---|---|---|
| `properties.center` | 数据提供方标定的市中心（**行政/商业中心**） | 最接近真实县城 |
| 几何 centroid | 多边形的形心（面积重心） | 差 20–35 km |
| 顶点平均 | 所有点的算术平均 | 差 40–50 km，**最差** |

后果：同一个问题「延吉到珲春多远」算出 **112.1 km**（用错了中心）vs **69.4 km**（用对了）。

**为什么差这么大？** 因为县界形状极不规则。延吉市辖区向西伸进龙井境内，几何形心落在山里，不是市区。

**修法：**

```python
def county_center(name: str) -> list:
    for f in data["features"]:
        if f["properties"].get("name") == name:
            p = f["properties"]
            # ① 优先用数据里标定的中心点
            if p.get("center") and len(p["center"]) == 2:
                return p["center"]
            # ② 退回几何形心
            xs, ys = [], []
            collect(f["geometry"]["coordinates"], xs, ys)
            return [sum(xs) / len(xs), sum(ys) / len(ys)]
    return None
```
