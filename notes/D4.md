## 二、今日提问记录（含答案）

### Q1：为什么代码要拆成 `index.html` / `style.css` / `app.js`，而不是都写在 html 里？

**第一层（反直觉的答案）：从浏览器角度，这两者完全一样。**

```html
<script src="app.js"></script>
```

浏览器做的事：① 下载 `app.js` ② **把里面的文字当成 JavaScript 执行**。
**效果和执行 `<script>里面的代码</script>` 一模一样。**

> ### 所以"放哪个文件"对浏览器没有区别 —— **区别只对人有意义。**
> **分离文件是"人类工程约定"，不是技术必需。**

**第二层：对人（工程）有四个区别**

| # | 区别 | 后果 |
|---|---|---|
| 1 | 可读性 | D5/D6 加完功能后，混在一起的文件会变成几百行，找一行 JS 要跳过几百行 HTML |
| 2 | 互不干扰 | 调样式不碰逻辑，改逻辑不碰结构 |
| 3 | 可复用 | 以后第二个页面直接 `<script src="app.js">` 就能用 |
| 4 | 浏览器缓存 | `app.js` 下载一次就缓存住，**内联代码每次刷新都重传** |

**第三层：类比**
内联 = 把正文、图表、参考文献全塞进论文一页里（能读，但改一个字要重排版整页）。
分离 = 分开放，改哪部分动哪部分。

**⚠️ 拆文件时的关键坑（加载顺序）**
`app.js` 里用到了 `L`（Leaflet 的函数）。**如果 `app.js` 比 `leaflet.js` 先执行 → 报 `L is not defined`。**

```html
<!-- ✅ 正确顺序：先库，后自己的代码 -->
<script src="https://unpkg.com/leaflet@1.9.4/dist/leaflet.js"></script>
<script src="app.js"></script>
```
同理 CSS：**先 `leaflet.css`，后 `style.css`**（后面的能覆盖前面的）。

**路径要用相对路径**：`href="style.css"` ✅ ／ `href="/style.css"` ⚠️（现在能用，部署到子路径会挂）

### Q2：`app.py` 和 `app.js` 各自是什么职责？

**先记住一件事：名字像，但它们没关系。** `.py` = Python（后端），`.js` = JavaScript（前端）。"app" 是 application 的缩写，两个都叫 app 纯属巧合。

**一句话区分：**
> **`app.js` 在浏览器里跑** → 负责"看"和"点"
> **`app.py` 在 8001 那个终端里跑** → 负责"算"和"给数据"

| | `app.js` | `app.py` |
|---|---|---|
| 语言 | JavaScript | Python |
| **在哪运行** | **浏览器**里 | **服务器**（终端） |
| **谁能看到代码** | ⚠️ **任何人**（F12 → Sources） | ✅ 只有你 |
| 能干什么 | 改页面、画地图、发请求、响应点击 | 读文件、查数据库、调大模型 API、用密钥 |
| **不能干什么** | ❌ 读服务器文件 ❌ 用密钥 | —— |
| 生命周期 | **每次刷新页面重新开始** | 一直跑着（`--reload` 只在改代码时重启） |

**最关键的一条**：**`app.js` 是"公开的"** —— 任何人 F12 就能看到全文。**所以密钥绝对不能放这里**（这就是 `.env` 存在的意义）。

**用项目里的真实代码对照：**

`app.js` 里：
```js
const res  = await fetch('http://localhost:8001/api/stats');
const data = await res.json();
```
翻成人话：**"喂，8001 那个服务，把统计数据给我。"**

`app.py` 里：
```python
@app.get("/api/stats")
def stats():
    with open("yanbian.geojson", "r", encoding="utf-8") as f:
        data = json.load(f)
    ...
    return {"要素总数": len(features), "县市列表": names}
```
翻成人话：**"好，我去读文件、数一遍，算好了给你。"**

> **`fetch` 和 `@app.get("/api/stats")` 是同一个动作的两端——一个是"问"，一个是"答"。**

**完整流程（拿本项目走一遍）**
```
① 浏览器访问 localhost:8000
② 8000（python -m http.server）返回 index.html
③ 浏览器继续下载 style.css、app.js、leaflet.js
④ 【app.js 执行】
   ├─ 建地图、加高德底图
   ├─ fetch('./yanbian.geojson')        ← 从 8000 拿自己项目里的文件
   └─ fetch('...:8001/api/stats')       ← 跨到 8001！
⑤ 【app.py 执行 stats()】读 geojson → 数出 8 个县市 → 返回 JSON
⑥ app.js 拿到 JSON → 用 DOM 画到侧栏
```
**第 ④ 步里两个 fetch 的区别，就是"前端"和"后端"的分界线。**

**餐厅类比**

| 项目 | 类比 |
|---|---|

## 三、核心知识

### 1. 作用域（scope）—— 今天最值钱的一条

```js
async function loadMap() {
  const data = await res.json();   // ← data 是【函数内部的局部变量】
  ...
}                                   // ← 函数一结束，data 就"消失"了

// 函数外面（顶层）：
const layer = L.geoJSON(data, ...)  // ❌ ReferenceError: data is not defined
```

**规则：函数内部定义的变量，外面访问不到。**

类比：你在**自己房间里**放了一本书（`data`），客厅里的人（顶层代码）找不到它。**要用，得进房间去用。**

**所以点击处理应该写在 `onEachFeature` 里面**——那里本身就在 `loadMap()` 内部，能拿到 `data`，也能拿到每个要素 `f`。

### 2. 变量提升（hoisting）—— 为什么 `loadMap()` 能写在文件末尾

| 写法 | 名字 | 能不能先调用后定义 |
|---|---|---|
| `function loadMap() {}` | **函数声明** | ✅ **能**（整体提升到作用域顶部） |
| `const loadMap = () => {}` | **函数表达式**（箭头函数） | ❌ **不能**（必须先定义后调用） |

Console 验证实验：
```js
// 能跑 ✅
hello();
function hello() { console.log('hi'); }
```
```js
// 报错 ❌ Cannot access 'bye' before initialization
bye();
const bye = () => console.log('bye');
```

### 3. CSS 层叠（Cascade）—— CSS 名字里的第一个字

**同一个选择器写两次，同优先级下"后面写的生效"。**

```css
#map { height: 100%; }              /* 第 7 行 */
...
#map { flex: 1; height: 100%; }     /* 第 22 行 ← 实际生效的是这个 */
```

**为什么危险**：你以为改第 7 行生效了，实际生效的是第 22 行 → **改了没反应，排查半天找不到原因**。

> **规则：同一份 CSS 里，不要重复定义同一个选择器。**

### 4. `white-space` —— 让 `textContent` 里的 `\n` 真正换行

**问题**：`textContent` 是纯文本，而 **HTML 默认把换行符和连续空格折叠成一个空格**。

| 值 | 效果 |
|---|---|
| `normal`（默认） | 换行和连续空格**全部折叠**成一个空格 |
| **`pre-line`** | **保留换行**，折叠多余空格 ← 换行场景用这个 |
| `pre-wrap` | 换行和空格**全保留**（像记事本） |

```css
#feature-info {
  white-space: pre-line;
}
```

### 5. 今天学的调试工具箱（**比任何代码都值钱**）

| 工具 | 用途 |
|---|---|
| **F12 → Elements → 选中元素 → Styles 面板** | 看**哪些 CSS 规则实际生效了**。被划掉 = 被覆盖；找不到 = 没加载 |
| **`getComputedStyle(元素).属性`** | 查浏览器**实际算出来的样式值**（权威方法，不靠眼睛猜） |
| **F12 → Network → 勾选「Disable cache」** | ✅ **开发时一直勾着**，否则改了不生效 |
| **`Ctrl + Shift + R`** | 硬刷新，忽略缓存重拉所有文件 |
| **F12 → Console** | 看 JS 报错，**先看报错来自哪个文件**：`app.js` 是你的，`content.js` / `chrome-extension://` 是扩展的 |

## 四、今日错误记录（重点复习区）

### 错误 1：孤儿代码 → `data is not defined`（作用域问题）

**错误代码**（挂在 `app.js` 文件末尾）：
```js
const layer = L.geoJSON(data, {    // ❌ data 在顶层不存在
  style: {},
  onEachFeature: (feature, lyr) => { ... }
}).addTo(map);
```

**三个问题**：
1. **`data` 未定义**（它在 `loadMap()` 内部，顶层看不到）→ `ReferenceError`
2. 就算能跑，也是**重复建图层**（`loadMap()` 里已经建过一次了）
3. 参数名用了 `feature`，而 `loadMap()` 里用的是 `f` → 又一个未定义变量

**正确做法：把点击处理搬进 `loadMap()` 的 `onEachFeature` 里**

```js
const layer = L.geoJSON(data, {
  style: { color: '#c00', weight: 1.5, fillColor: '#f66', fillOpacity: 0.2 },
  onEachFeature: (f, lyr) => {
    // 弹窗（D1 原有）
    lyr.bindPopup(f.properties.name || '未命名');

    // 点击后显示到侧栏 + 让 AI 生成介绍（D4 新增）
    lyr.on('click', async () => {
      const name = f.properties.name || '未命名';
      document.getElementById('feature-info').textContent = `你选中了：${name}`;
      try {
        const res = await fetch(
          'http://localhost:8001/api/chat?q=' + encodeURIComponent(`用一句话介绍${name}`)
        );
        const data = await res.json();
        document.getElementById('feature-info').textContent =
          `你选中了：${name}\n\n${data.回答}`;
      } catch (err) {
        document.getElementById('feature-info').textContent = `你选中了：${name}（介绍生成失败）`;
      }
    });
  }
}).addTo(map);
```

> ⚠️ **参数名必须统一**：`onEachFeature: (f, lyr)` 里就只能用 `f`。
> **抄模板时这是最容易踩的坑**——模板用 `feature`，你自己的代码用 `f`。

### 错误 2：CSS 改了不生效（**这次是"排查"，不是"代码错"**）

**现象**：`#feature-info { white-space: pre-line; }` 写对了，但页面没换行。

**推理过程（这个是重点）**：
1. 左右两栏布局生效 → 说明 `style.css` **加载成功了**（不可能是 404）
2. 但 F12 → Styles 面板里**只有浏览器的默认规则** `div { display: block; }`，**没有 `#feature-info`**
3. **两条合起来只有一个解释**：浏览器加载的是 `style.css` 的**旧版本**（缓存）

**修法**：F12 → 网络 → 勾选「Disable cache」→ 刷新 → 生效 ✅

**验证用的两行命令**：
```js
// ① CSS 生效了吗？
getComputedStyle(document.getElementById('feature-info')).whiteSpace
// "pre-line" = 生效 ； "normal" = 没生效

// ② 字符串里有没有换行符？
document.getElementById('feature-info').textContent.includes('\n')
// true = JS 没问题，是 CSS 问题
// false = 走到了 catch 分支，是 JS 问题
```

> **这两行命令的价值**：把"CSS 问题"和"JS 问题"彻底分开。**不靠猜，靠看。**

## 七、高频易错点汇总（D4）

1. **函数内部的变量，外面访问不到**（`data is not defined` 的根源）⭐
2. **`function f(){}` 会提升，`const f = () => {}` 不会** —— 决定了能不能"先调用后定义"
3. **参数名要统一**：`onEachFeature: (f, lyr)` 就只能用 `f`；抄模板最容易错这里
4. **CSS 重复定义 → 后面覆盖前面**（改了没反应，很可能改的是被覆盖的那条）
5. **`white-space: pre-line`** 才能让 `textContent` 里的 `\n` 换行
6. **改了 CSS/JS 不生效** → 先查缓存（Disable cache + 硬刷新），再查代码
7. **`<script src>` 与自己写 `<script>` 内容，对浏览器是一样的** —— 分离是为了人
8. **加载顺序**：先 leaflet.js，后 app.js（否则 `L is not defined`）
9. **CORS 是后端的责任**（前端跨端口调用被拦，要在后端开权限）
10. **`innerHTML +=` 拼用户输入有 XSS 隐患** —— D5/D6 会讲怎么防
